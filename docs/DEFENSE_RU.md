# Разбор перед защитой

Это учебный разбор AI-assisted решения. Прочитай код, проверь его на маленьких примерах и объясни алгоритмы своими словами. На самой защите пользуйся только тем, что разрешает преподаватель.

## Что делает программа

В `data/walls.txt` записаны стены между клетками. В `data/slides.txt` записаны отдельные односторонние переходы: они игнорируют стены. Не путай путь по лабиринту и самый дешёвый маршрут по зонам: это разные задачи.

## 0. DisjointSet.java

DSU хранит группы связанных клеток. `parent[x]` показывает родителя, а у корня родитель равен самому себе. `find` сначала находит корень, затем вторым циклом направляет все посещённые клетки прямо к нему. `union` соединяет корни двух разных групп: маленькую группу подвешиваем к большой, уменьшаем число групп и возвращаем `true`. Если корни уже одинаковые, возвращаем `false`: добавление связи создало бы цикл.

Пример: после `union(0,1)` и `union(1,2)` клетки 0, 1, 2 в одной группе. `union(0,2)` вернёт false. `size` имеет смысл у корня группы; размеры остальных узлов больше не используются.

## 1. Maze.breakWalls

Берём стены строго в порядке файла. Разрушаем стену только тогда, когда `union` вернул true. В начале 121 отдельная клетка; чтобы получить одну группу, нужно 120 успешных объединений. Из 220 стен остаётся 100. Последняя разрушенная стена имеет номер 161: в массиве это индекс 160, потому что индексы начинаются с нуля.

## 2. Maze.cheapestMaze и primCost

Kruskal сначала сортирует номера стен по стоимости. Затем применяет то же правило DSU: берёт дешёвую стену, если она соединяет разные группы. Это минимальное остовное дерево: все клетки связаны, циклов нет, сумма стоимостей минимальна.

Prim начинает с клетки 0 и хранит доступные стены в очереди с приоритетом. Из очереди берёт самую дешёвую стену к новой клетке, включает клетку в дерево и добавляет её выходящие стены. Если оба конца очередной стены уже в дереве, пропускает её. В нашем варианте оба алгоритма дают 32192. Сумма хранится в `long`, чтобы не переполнить `int` на больших входах.

## 3. Escape.escape

В дереве есть ровно один простой путь между любыми двумя клетками. DFS идёт в глубину, проверяя вверх, вправо, вниз, влево. `stack` хранит текущий путь, а `direction` — какое направление проверять следующим при возвращении в клетку. Если направлений больше нет, снимаем клетку со стека. Так программа работает без рекурсивных вызовов и не переполняет стек JVM.

При первом посещении выхода текущий стек и есть ответ. В пути 27 клеток, поэтому перемещений 26. DFS успел посетить 48 клеток: некоторые были в тупиковых ветках, поэтому это число больше длины пути. Тупик — клетка с одной открытой дверью; их 33 во всём лабиринте, включая старт или выход, если у них одна дверь.

## 4. Zones.kosaraju

Зона, или SCC, — группа клеток, где из каждой можно добраться до любой другой по направленным переходам. Первый проход DFS идёт по исходным стрелкам и записывает клетки в момент завершения обработки. Второй проход берёт их в обратном порядке завершения и идёт по перевёрнутым стрелкам; каждый новый обход получает новый номер зоны.

Если оставить исходные стрелки во втором проходе, можно случайно захватить следующие зоны. В перевёрнутом графе выбранная зона не ведёт в ещё не обработанные зоны. Номера получаются в топологическом порядке: межзонные стрелки всегда идут от меньшего номера к большему. Здесь 8 зон, самая большая содержит 23 клетки. Граф не DAG, потому что есть зоны с несколькими клетками; петли из клетки в саму себя в условии запрещены.

## 5. Zones.routes

Заменяем каждую зону одной вершиной. Переходы внутри неё убираем, потому что движение внутри зоны бесплатно. Если между двумя зонами несколько переходов, оставляем минимальную стоимость через `merge(..., Math::min)`.

Для самой длинной цепочки `stages` сначала содержит единицы: даже одиночная зона — цепочка длины 1. Для ребра X → Y делаем `stages[Y] = max(stages[Y], stages[X] + 1)`. Самая длинная цепочка может начинаться где угодно, поэтому её расчёт не ограничен стартовой зоной. Здесь максимум равен 5.

Для стоимости `distance` сначала содержит бесконечность, а для стартовой зоны — 0. Если X достижима, обновляем `distance[Y] = min(distance[Y], distance[X] + cost)`. Идём по номерам зон один раз: все предшественники уже обработаны, поэтому очередь с приоритетом не нужна. Ответ для зоны выхода — 7. Если старт и выход в одной зоне, стоимость будет 0.

## Что стоит уметь показать

Запусти `java tools/Check.java`, затем `java -cp out Main` и открой `output/maze.html`. Найди в коде место сортировки Kruskal, очередь Prim, увеличение счётчика DFS, запись времени завершения в Kosaraju и обе формулы обновления в routes. Вручную пройди пример `examples/tiny`: 3 разрушенные стены, MST 31, путь 2, 3 зоны и стоимость маршрута 9.

Проверь себя: почему DFS visited может быть больше Path length + 1? Почему нельзя просто брать самые дешёвые стены без DSU? Почему число зон равно числу клеток только у DAG при отсутствии петель? Почему алгоритм маршрута не использует Dijkstra? Ответы должны следовать из кода, а не только из заученных формулировок.
